0) Prompt System Architecture
0.1 Prompt building blocks

Use 3 layers for every LLM call:

System prompt (constant, strict)

Output must be valid JSON

No extra commentary

Use only provided evidence

If missing info → mark as unknown + add gaps

Developer prompt (task spec)

Fields to extract

Rules for confidence scoring

Evidence linking requirements

User payload (runtime data)

Website content snippets (already scraped)

Social content snippets (optional)

Manual company answers (optional)

Current agent template (optional)

0.2 Response contract (universal)

All prompts return:

{
  "result": { },
  "confidence": { },
  "evidence": [ ],
  "gaps": [ ],
  "warnings": [ ]
}

Evidence object
{
  "field_path": "company_profile.services[0].name",
  "source_id": "src_web_03",
  "source_type": "website|social|manual",
  "source_url": "https://...",
  "quote": "short excerpt <= 25 words",
  "notes": "why this supports the field"
}

Gap object
{
  "gap_type": "missing_pricing|missing_hours|unclear_services|unknown_audience",
  "severity": "low|medium|high",
  "impact": "What the agent can’t do well without it",
  "recommended_fix": "Ask user / connect integration / add info manually",
  "question_to_user": "Exact question to ask"
}

Confidence scoring (standard)

0.90–1.00: strongly supported by explicit evidence

0.70–0.89: inferred from multiple hints, still plausible

0.40–0.69: weak inference (prefer confirm)

<0.40: unknown (do not fill; create a gap)

0.3 Prompt versioning

Store prompts in DB:

prompt_key (e.g., company_enrichment_v1)

version (int)

template (string)

schema_version (int)

created_at, updated_at

owner, notes

Log every call:

prompt_key+version

input hash

output JSON

latency

token usage

pass/fail schema validation

1) Company Enrichment Prompt (Website → Structured Profile)
Purpose

Turn scraped website/social/manual inputs into a reliable company_profile + brand_voice_profile + gaps.

Input payload
{
  "company_seed": {
    "name": "optional",
    "website_url": "https://example.com",
    "industry_hint": "optional",
    "timezone": "America/Dominica"
  },
  "sources": [
    {
      "source_id": "src_web_01",
      "type": "website",
      "url": "https://example.com/about",
      "content": "clean text snippet..."
    }
  ],
  "manual_answers": {
    "audience_summary": "optional",
    "primary_goal": "optional",
    "service_area": "optional"
  }
}

Output schema (result)
{
  "company_profile": {
    "name": "",
    "tagline": "",
    "industry": "",
    "sub_industry": "",
    "description": "",
    "services": [
      { "name": "", "description": "", "category": "" }
    ],
    "products": [
      { "name": "", "description": "" }
    ],
    "audience_segments": [
      { "segment": "", "needs": [], "pain_points": [] }
    ],
    "value_proposition": "",
    "service_area": "",
    "locations": [],
    "business_hours": "",
    "contact_channels": {
      "phone": "optional",
      "email": "optional",
      "whatsapp": "optional",
      "address": "optional"
    },
    "calls_to_action": ["book a call", "request a quote"]
  },
  "brand_voice_profile": {
    "formality": 0.0,
    "warmth": 0.0,
    "directness": 0.0,
    "enthusiasm": 0.0,
    "tone_keywords": [],
    "do": [],
    "dont": [],
    "sample_brand_sentence": ""
  }
}

System prompt (constant)

Return only valid JSON matching schema.

Do not invent facts. If not explicit, set empty/unknown and create a gap.

Every filled field must have evidence unless it’s from manual_answers.

Quotes ≤ 25 words.

Developer prompt (task rules)

Extract company name, industry, services, audience, value prop, hours, service area.

If multiple possible values conflict, choose the most supported and add a warning.
